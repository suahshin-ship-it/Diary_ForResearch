# Diary For Research

계획과 실제 활동을 날짜별로 나누어 기록하는 한국어 연구 다이어리입니다. React와 Vinext, Cloudflare D1을 사용합니다.

이 저장소는 기능 소스와 개발 문서만 포함합니다. 모든 날짜는 빈 기록으로 시작하며, 테스트는 가상의 날짜와 문구만 사용합니다. 개인 일정, 실제 활동, 운영 데이터베이스, 로그인 정보, 기존 배포의 식별자는 포함하지 않습니다.

## 주요 기능

- 날짜 이동과 날짜별 계획·실제 활동·진행 상태 저장
- 24시간 원형 시간표에서 계획 또는 실제 활동 확인
- 원형 선택기와 분 단위 입력으로 시간 범위 조절
- 시간칸 추가, 숨기기, 복원과 겹치는 시간 안내
- 한 줄 활동 입력과 색상을 고를 수 있는 스티커 메모
- 삭제한 메모의 내용 보존 및 복원
- 하루 요약, 개선점, 다음 작업을 직접 작성
- 로그인 사용자별 D1 데이터 분리와 revision 기반 저장 충돌 감지
- 인증된 MCP 도구로 날짜별 기록 읽기 및 계획 필드만 갱신

저장은 명시적인 버튼 동작입니다. 입력하거나 메모를 추가한 것만으로 서버에 저장되지 않습니다. 날짜 기준은 현재 `Asia/Seoul`이며, 자정을 넘는 시간 범위는 지원하지 않습니다.

## 로컬 개발

### 준비

- Node.js 22.13 이상 및 npm; 회귀 테스트에는 Node 내장 SQLite를 사용합니다
- 잠금 파일에 고정된 개발·선택 의존성을 설치할 수 있는 환경
- Windows, macOS, Linux의 일반 로컬 개발은 기본 `portable` 실행 방식 사용

```sh
npm run install:ci
npm run build
```

`.openai/hosting.json`은 로컬 빌드에 필요한 `DB` 바인딩과 MCP 기능 선언만 포함합니다. 운영 프로젝트 ID가 없는 것은 의도된 구성입니다. `vite.config.ts`의 데이터베이스 UUID는 로컬 시뮬레이션용 자리표시자입니다.

첫 빌드 후 새 로컬 데이터베이스에 초기 스키마를 한 번 적용합니다.

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_familiar_chameleon.sql
npm run dev
```

개발 서버가 출력한 loopback 주소를 엽니다. 기본 포트는 5173입니다. 같은 주소의 `/signin-with-chatgpt?return_to=/`에서 가상의 로컬 사용자로 로그인할 수 있습니다. 이 개발용 로그인은 loopback 연결에서만 동작하며 운영 빌드에는 포함되지 않습니다. 외부 공개를 위해 인증 검사를 제거하거나 개발 서버를 노출하지 마세요.

`npm start`는 빌드된 Worker의 로컬 확인용입니다. 개발용 로그인 시뮬레이션을 제공하지 않으므로, 일반적인 화면 개발과 합성 데이터 확인에는 `npm run dev`를 사용합니다.

### 명령

```sh
npm test                 # API·MCP 및 저장/복원 회귀 테스트
npm run typecheck        # TypeScript 검사
npm run lint             # 전체 ESLint 진단
npm run build            # 로컬 배포 산출물 생성; 배포하지 않음
npm run db:generate      # 스키마 변경 시 새 SQL 마이그레이션 생성
```

실제 검증 결과와 알려진 제한은 [DEVELOPMENT.md](DEVELOPMENT.md)를 참고하세요. 이미 적용한 SQL을 다시 실행하지 말고, 추가 마이그레이션은 순서대로 별도 적용합니다.

## 인증과 데이터

운영 환경에서는 신뢰할 수 있는 호스팅 계층이 검증한 사용자 정보를 전달해야 합니다. 앱의 `oai-authenticated-user-*` 헤더를 인터넷 요청자가 직접 주입할 수 있는 환경에 그대로 배포하면 안 됩니다. 다른 플랫폼에 배포하려면 인증 어댑터와 신뢰 경계를 먼저 구현하고 검증하세요.

- 서버는 사용자 ID와 날짜의 복합 키로 데이터를 조회·저장합니다
- 브라우저 저장은 같은 origin, JSON 형식, 데이터 크기와 스키마를 검사합니다
- 다른 화면에서 기록이 바뀌면 자동 덮어쓰기 대신 충돌을 알립니다
- MCP 계획 갱신은 실제 활동, 상태, 메모, 회고를 보존합니다
- Git은 기록 보관함이 아닙니다. 데이터베이스 파일과 환경 파일은 커밋하지 않습니다

## 연동 상태

Notion 동기화, 예약 자동 요약, 외부 브리핑의 정기 실행은 아직 연결되지 않았습니다. MCP 엔드포인트가 구현되어 있어도 클라이언트 등록, 인증 및 정기 실행 설정을 대신하지 않습니다. 브라우저의 `document.modelContext` 지원 여부에 따라 화면 내 보조 도구 사용 가능 여부도 달라집니다.

## 배포와 저장소의 관계

GitHub 소스 변경만으로 기존 비공개 Site가 자동 배포되거나 운영 데이터베이스가 마이그레이션되지 않습니다. 이 저장소에는 자동 배포 워크플로와 기존 Site 연결 정보가 없습니다. 공개 소스 준비 과정은 기존 운영 Site와 데이터를 변경하지 않습니다.

새 환경에 배포하려면 별도의 프로젝트, 인증, 저장소 바인딩과 접근 정책을 설정하고 배포 및 마이그레이션을 각각 검토해야 합니다. 운영 자격 증명이나 프로젝트 식별자를 공개 저장소에 추가하지 마세요.

## 코드 구성

- `app/`: 화면, 원형 시간 UI, API, MCP, 인증 어댑터
- `lib/diary-data.ts`: 데이터 타입, 빈 날짜, 검증 및 시간 유틸리티
- `lib/diary-store.ts`, `db/`, `drizzle/`: D1 접근과 스키마·마이그레이션
- `tests/test-diary.mjs`: 가상 데이터 기반 회귀 테스트
- `build/`, `scripts/`: 로컬 인증·바인딩 시뮬레이션과 빌드 지원
- `components/`, `hooks/`, `vendor/`: 기반 UI 구성 요소와 스타일
